# Explicit consent and host leadership for shared dungeon runs

Existing multiplayer participation permits either character owner to advance a
run, but party membership alone does not establish consent to join or readiness
for the next encounter. Shared runs therefore require a pairing formed through
an accepted dungeon invitation (which can continue through Play again together),
one owned character from each of two players, and both players' fresh readiness
before each encounter; the inviter leads dungeon selection, path choices, and
encounter starts while character control remains with each owner. Keeping the roster fixed
from run start and waiting for disconnected owners, rather than substituting
players or handing over characters, preserves those ownership and consent
boundaries at the cost of requiring both players to coordinate their return.

All of these decisions are scoped to an individual dungeon run. Players and
characters can participate in other runs concurrently; a waiting friend does not
reserve their account or character across the game.

This records the accepted design; implementation has not started. The complete
specification is published as
[issue #2](https://github.com/ChristianSchneeweiss/game/issues/2), with the
interaction decisions recorded in [the feature design](../friends-design.md).
